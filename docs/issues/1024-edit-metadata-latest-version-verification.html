1. Original issue (exact requirement)

Product rule (JSF parity): No matter which historical dataset version the user is viewing, clicking Edit Metadata must pre-fill the form with the latest metadata (:latest = draft if present, else latest published).

SPA bug: The form was pre-filled from the browsed version in the URL (?version=1.0), so older fields appeared and newer values could be overwritten on save.

Scenario dataset (from the issue)

VersionTitleSubtitle
1.0Test Dataset(empty)
2.0 (latest published)Test DatasetMy Subtitle

User action: open Version 1.0 → Edit Dataset → Metadata.

2. What was parsed / loaded wrongly (BEFORE)

Bug path
Browse ?version=1.0 → Menu writes URL version=1.0 → Factory reads URL version → Fetch API versions/1.0 → Form defaults = v1 blocks

Wrong Factory logic (before)

// EditDatasetMetadataFactory.tsx — BEFORE (bug)
const searchParamVersion = searchParams.get('version') ?? undefined
const version = searchParamVersionToDomainVersion(searchParamVersion)
// If URL is ...&version=1.0  →  version === "1.0"
// DatasetProvider fetches that historical version

  "doi:…",

API equivalent: .../versions/1.0

(empty — Version 1 metadata)

3. What was fixed (AFTER)

Fixed path
Browse ?version=1.0 → Menu may still pass version=1.0 in URL → Factory ignores URL version → Fetch :latest → Form defaults = latest blocks

Same pattern as EditDatasetTermsFactory (already correct in this repo).

Fixed Factory logic

// EditDatasetMetadataFactory.tsx — AFTER (fix)
const persistentId = searchParams.get('persistentId') ?? undefined
// Always load the latest version (draft if exists, otherwise latest published).
// Ignore the browsed `version` query param (IQSS/dataverse-frontend#1024).
const version = DatasetNonNumericVersion.LATEST  // ":latest"

return (
  <DatasetProvider
    repository={datasetRepository}
    searchParams={{ persistentId, version }}>
    <EditDatasetMetadata ... />
  </DatasetProvider>
)
After · fetch argument 
getByPersistentId(
  "doi:…",
  ":latest",     // ← DatasetNonNumericVersion.LATEST
  undefined,
  true
)

API equivalent: .../versions/:latest

:latest = draft if one exists, else latest published (here Version 2.0).

After · form output (correct)
Test Dataset
My Subtitle

PASS vs issue expectation

Matches JSF: latest metadata pre-populated.

C. Manual product verification (original issue scenario)

  2. Add subtitle My Subtitle, publish Version 2.0.
  3. Open SPA: /datasets?persistentId=…&version=1.0 — browse still shows empty subtitle.
  4. Click Edit Dataset → Metadata.
  5. PASS if Subtitle input = My Subtitle.
  6. FAIL if Subtitle is empty.
  7. Optional DevTools check: dataset fetch uses version :latest, not 1.0.

D. Negative control (must not break browse)

On ?version=1.0 without opening Edit Metadata, the dataset page must still show Version 1 content (empty subtitle). If browse also shows latest, the fix was applied too broadly.
